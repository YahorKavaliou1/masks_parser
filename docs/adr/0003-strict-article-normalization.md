# 0003. Строгая нормализация артикула без автоисправлений

Статус: принято

## Контекст

В выгрузках встречаются нижний регистр, неразрывные пробелы, дефисы, переводы строк, кириллица вместо латиницы и путаница «O/0», «I/1». ТЗ задаёт ровно пять правил нормализации.

## Решение

- Исходный артикул хранится без изменений. Сопоставляется отдельный поисковый ключ (`ArticleNormalizer`): латинские `a–z` переводятся в верхний регистр, неразрывные пробелы заменяются обычными, по краям удаляются только обычные пробелы.
- Больше ничего не исправляется. Кириллица не заменяется латиницей, «O» и «0» остаются разными символами, внутренние пробелы, дефисы и переводы строк уходят в исключения.
- Ключ сверяется с маской целиком (`re.fullmatch`), а не через `^…$`: в Python `$` пропускает перевод строки в конце.
- Артикул, который подходит сразу под несколько масок, тоже исключение: по ТЗ принятый артикул соответствует ровно одной маске.
- Решает только матчер. `MismatchExplainer` лишь подбирает человекочитаемую причину, а невидимые символы показывает как `U+XXXX`.

## Последствия

- Ни один артикул не попадает в сертификат за счёт «догадки» программы.
- Если в каталоге опечатка вроде русской «А», товар окажется в исключениях. Причина укажет символ и позицию, так что опечатку легко исправить в учётной системе.
